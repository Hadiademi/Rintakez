# Chat UX Implementation Plan

> Executed subagent-driven (implementer + review per task). Derived from a live visual inspection (desktop 1440 + mobile 390) and a 3-lens chat-UX code audit. Goal: make the in-app messaging feel like a real modern chat (WhatsApp/iMessage/Airbnb standard) on both desktop and mobile.

**Tech:** Next.js 16 + React 19 + TS, Supabase realtime, Tailwind v4, next-intl (de/fr/en). Primary files: src/components/message-thread.tsx, src/components/conversation-list.tsx, src/components/messages-shell.tsx, src/components/mobile-tab-bar.tsx, src/app/[locale]/layout.tsx, src/app/[locale]/(app)/messages/{page,layout}.tsx + [id]/page.tsx, src/lib/actions/messages.ts, src/i18n/messages/{de,en,fr}.json.

## Global Constraints
- No payment code. No web regression: `npm run typecheck && npm run lint && npm run build && npx vitest run` green after each task.
- Mobile-parity: every change must work on mobile AND desktop (project rule).
- i18n: every new user string in de/fr/en; French informal **tu**.
- Preserve the existing realtime + mark-as-read + block/report behavior; do not regress it.
- Match existing design tokens (bg-ink/text-paper/surface/line/mute, press, label).

## Task CH1 — Viewport, keyboard & thread-height foundations (mobile)
Files: src/app/[locale]/layout.tsx, src/components/message-thread.tsx, src/app/[locale]/(app)/messages/layout.tsx.
- Add a `viewport` export with `viewportFit: "cover"` + `interactiveWidget: "resizes-content"` so env(safe-area-*) actually resolves in the installed PWA and 100dvh shrinks with the keyboard.
- Composer textarea (and thread inputs) → 16px on touch (`text-base lg:text-[14px]`) to stop iOS focus-zoom.
- Replace the magic-number thread height (`100dvh-12rem`) with a robust flex column that owns the viewport (header/banner in-flow, scroller `flex-1 min-h-0`), using dvh; add `overscroll-contain` to the thread + sidebar scrollers.
- Acceptance: composer sits above the tab bar on mobile (incl. safe area), no iOS zoom on focus, no page rubber-band/pull-to-refresh inside the thread.

## Task CH2 — Thread rendering overhaul (the core)
File: src/components/message-thread.tsx (+ i18n keys). One cohesive rewrite of the render + send path (these concerns are entangled):
- **Optimistic send:** append a temp-id message with status `sending` before awaiting; on success reconcile to the server id (dedupe exists); on failure mark `failed` with a retry/delete affordance and restore nothing (the bubble carries the text). Wrap send in try/catch/finally; on catch keep the bubble as failed; always clear the `sending` guard in finally; refocus the composer after send.
- **Smart auto-scroll:** track near-bottom (~120px); only auto-scroll on new message when near-bottom OR the message is mine; instant scroll on first mount (`behavior:auto`), smooth after — gated by `prefers-reduced-motion`. Floating "Neue Nachrichten ↓" pill when a message arrives while scrolled up.
- **Message grouping:** group consecutive same-sender messages within ~5 min; tight spacing within a group; render the hh:mm timestamp only on the last message of a group. Move the per-message Report to a hover (desktop) / long-press affordance so it isn't under every bubble.
- **Day separators:** bucket by LOCAL date (not UTC slice); label the last two days as `Heute`/`Gestern` (localized) else a localized medium date via next-intl `useFormatter`.
- **Composer keys:** Enter sends only on fine pointers (`matchMedia('(pointer:fine)')`); on touch Enter = newline + rely on Send button; add `enterKeyHint="send"`; guard `if (e.nativeEvent.isComposing) return;`.
- **Read receipts:** on own messages show ✓ (sent) / ✓✓ (read) using the conversation's other-party `*_last_read_at` (already selected in getConversations / available to the thread) — compare message.created_at to the other side's last-read timestamp.
- **a11y/robustness:** the scroller gets `role="log" aria-live="polite"` + localized aria-label + tabIndex=0; bubbles get `break-words`/`[overflow-wrap:anywhere]`; textarea gets an accessible name + `maxLength={4000}`; sr-only sender prefix per bubble (`t('you')`/other name); back button gets a 44px hit area + `aria-label={t('back')}`; block/report get ≥44px hit areas.
- **i18n:** de/fr/en for: today, yesterday, newMessages, back, you, unread, retry, sendFailed, limitReached (friendly), plus fix the French block notices to informal **tu**. Map `limit_reached` from the send action to the friendly message.
- Acceptance: sending shows an immediate bubble with pending→sent/✓✓; failed send is retryable; reading history is not yanked to the bottom (pill appears instead); consecutive messages group with one timestamp; separators show Heute/Gestern; Enter behaves per pointer type; screen-reader announces new messages; long URLs wrap.

- Acceptance: opening a long thread loads fast (only newest N), older messages load on demand, realtime still appends new ones.
